Install Prisma and Connect to Neon

Exercise 1 / 5 . Level 1 . 25 min

Goal: get Prisma into yesterday's Next.js project and pointed at a Postgres database I do not have to run myself. We are using Neon -- serverless Postgres in the cloud -- which is the right call for a cohort because there is nothing to install and it behaves the same on every machine. For me it is also a useful contrast: every database I have touched in this program lived inside Cloudflare's edge (KV). This one lives somewhere I connect to over a URL.

Neon signup

Signed in with GitHub, created a project named nextchapter-week6, picked the closest region, left the Postgres version default. Neon then shows a connection string starting with postgresql://. I copied it somewhere safe and treated it like a password, because it is one.

Footgun: Neon gives you TWO connection strings

The dashboard defaults to a pooled string (the host has -pooler in it) and offers a direct one if you expand the options. The pooled one routes through Neon's connection pooler, which is what you want for a serverless app making lots of short-lived connections. For schema operations -- db push and migrations -- the direct connection is the cleaner choice. For this week I set DATABASE_URL to the pooled string and it works fine for db push; in Week 8 when we add real migrations I will add a separate DIRECT_URL for those. Flagging it now so the distinction is not a surprise later.

Install

npm install prisma --save-dev
npm install @prisma/client
npx prisma init

prisma init created two things: prisma/schema.prisma (the schema file, with a default generator and a postgresql datasource) and .env (with a placeholder DATABASE_URL). Nothing surprising; this is the same "scaffold a few files" move create-next-app made yesterday.

Guarding the secret

Before I pasted anything real, I checked .gitignore. Next.js already had .env* in there, so the connection string will not get committed. I verified it instead of trusting it: 

$ git check-ignore .env
.env
Why I ran git check-ignore instead of just eyeballing .gitignore

Eyeballing tells you a pattern exists. git check-ignore tells you the file is actually ignored by the rules as they resolve, which is the thing I care about. It prints the path if ignored and nothing if not. A silent prompt would have meant my Neon credentials were one git add . away from being public. This is a thirty-second check that prevents a class of mistake I do not want to make with someone's reentry data downstream.

Then I opened .env and replaced the placeholder with the real Neon string, verbatim, including ?sslmode=require at the end: 

DATABASE_URL="postgresql://USER:PASSWORD@HOST-pooler.neon.tech/DBNAME?sslmode=require"

The schema.prisma it generated

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

Reads cleanly: generate a JS client, and connect to postgres at the URL in my env. The env("DATABASE_URL") indirection is the whole reason the secret stays out of the committed file -- the schema references the variable, never the value.

Proving the connection

$ npx prisma db push

Your database is now in sync with your Prisma schema. Done in 1.2s

The schema has no models yet, so this pushed an empty schema. That is fine -- the point of this step was not to create tables, it was to prove the credentials, the SSL, and the network path all work end to end before I start defining models. Get the boring connectivity confirmed first, then build on solid ground.

Footgun: the first query is slow because Neon autosuspends

Neon's free tier suspends the compute after a few minutes of inactivity. The first command after a nap takes a couple of seconds while it wakes up; subsequent ones are instant. I recognized this immediately because it is the exact same cold-start behavior I deal with on Cloudflare Workers. It is not a bug and it is not my connection string -- it is the database waking up. Worth knowing so I do not chase a phantom "slow Prisma" problem.

Checkpoint

Prisma installed, .env holds a real Neon string and is verifiably gitignored, and db push round-trips to the cloud. The connection is proven. Next: give it something to create.
