Add AI to Your Zap

Exercise 2 / 5 . Level 1-3 . 35 min

This is where the tool stops being an email rule and becomes something else. Exercise 1 moved data from one place to another -- useful, but replaceable by a mail filter. Adding an AI step in the middle means the Zap can interpret language. The email body is unstructured; the AI reads it and returns a classification the downstream actions can act on without any human involved. That is the line between forwarding and processing.

Step 1 -- Add the AI by Zapier action

I inserted an AI by Zapier step between the Filter and the Slack action. AI by Zapier calls gpt-5-mini internally -- no API key needed, the cost comes out of Zapier's plan instead of my OpenAI account, which matters for keeping client costs predictable. 

Step:   AI by Zapier
Model:  gpt-5-mini (internal)
Input:  {{ trigger.body_plain }}

Prompt (Level 1 -- initial version):
  Classify the urgency of this intake message.
  Return one of: urgent, normal, spam.

  Message: {{ trigger.body_plain }}

I ran a test with an intake body that read: "D. has a parole check-in next Thursday at 9am." Level 1 result: the step ran, the model returned text, and I could see the output in the step preview. So far so good.

Step 2 -- The bug (Level 3 sets this up)

I wired the AI output into a Path. Level 2 adds the Path: one branch for urgent that sends an immediate Slack message, one for normal that does nothing yet (we log in Exercise 3), one for spam that halts. The Path condition is an exact-match filter: {{ step.ai_output }} equals urgent.

The test failed. The urgent branch did not fire on an obviously urgent message. I looked at the AI step output and saw the problem immediately: 

AI output (without one-shot example):
  "Urgent."

Capital U. Trailing period. My exact-match condition was urgent (lowercase, no period). The model was returning valid semantic content but in a format my filter could not act on. This is a prompt engineering problem, not a Zapier problem. The fix is a one-shot example in the prompt that shows the model the exact output format I need.

Step 3 -- The fix (Level 3)

Prompt (Level 3 -- with one-shot example):
  Classify the urgency of this intake message as exactly one of:
  urgent, normal, or spam.
  Return only the single word, lowercase, no punctuation.

  Example:
  Message: "court date tomorrow morning 8am"
  Output: urgent

  Now classify this message:
  Message: {{ trigger.body_plain }}
Before vs. after

Before the one-shot: the model returned "Urgent." -- semantically correct, format wrong, exact-match broke.

After the one-shot: the model returned "urgent" -- correct value, correct format, Path works as intended.

The lesson is that a language model will follow instructions about what to return, but it will apply its own formatting conventions unless you show it what the output should look like by example. A single worked example is cheaper and more reliable than adding more words to the instruction. I have seen this before in code-generation prompts; the principle is the same here.

Step 4 -- The Path (Level 2)

Path A -- condition: {{ ai_step.output }} (Text) Exactly matches "urgent"
  Action: Slack -- send message to #on-call
    "URGENT intake: {{ trigger.subject }}"

Path B -- condition: {{ ai_step.output }} (Text) Exactly matches "normal"
  Action: (none yet -- Exercise 3 adds Sheets logging)

Path C -- condition: {{ ai_step.output }} (Text) Exactly matches "spam"
  Action: Filter halts (no downstream action)

With the fixed prompt, I tested three messages:

Body textExpectedAI outputPath taken
"parole check-in tomorrow 8am"urgenturgentA -- Slack fires
"forklift cert class next Monday, needs reminder"normalnormalB -- no action yet
"click here to claim your free gift card"spamspamC -- halted
What the Path buys over a single action

Without the Path, every message that passes the Filter would go to the same downstream action. With the Path, urgent messages get a phone ping, normal messages get a log entry, and spam dies at the gate. This is the difference between "automation" and "triage." The AI classifies; the Path routes. Neither step is doing the other's job.

Deliverable

A Zap with an AI classification step (gpt-5-mini, one-shot prompt, exact lowercase output), a three-branch Path driven by the classification, and three documented test runs -- one per branch -- all hitting the correct path. The one-shot prompt bug is documented with before/after, because it is the kind of thing that bites people silently: the model was never wrong, the prompt was just not precise enough to constrain the format. One example fixed it.
