Empty State On The Board

Exercise 2 / 5 . Level 1 . 30 min

Goal: make the board say something useful when it has nothing to show. Right now a board with zero rows renders an empty grey area, which to a first-time user is indistinguishable from a page that failed to load. This is Must-Have number four, and the reason it earned a Must rather than a Should is the same answer I defended at the Day 1 gate -- my one user opens an app with zero rows in it, so for him the empty state is not an edge case, it is the entire first screen. I deployed it this morning; now I make sure the first thing he sees on it is a welcome and not a void.

There are two empty states, not one

This is the part I almost got wrong. "Empty" is not a single situation. There is the brand-new board -- nothing has ever been added -- and there is the filtered-to-zero board -- there is data, but the current type filter matches none of it. The same blank grid, two completely different truths, and the welcome copy that is perfect for the first case is an actual lie in the second. If he has three jobs saved, taps the "cert" chip, and sees "Welcome! Add your first one," the app just told him something false.

The JSX

The board already knows two numbers: how many opportunities exist at all, and how many survive the current filter. That is enough to branch cleanly. If nothing exists, show the welcome. If things exist but the filter emptied the view, show the reassuring filter message with the active type named. Otherwise, render the grid. 

// app/Board.jsx -- branch on total vs filtered counts
function Board({ opportunities, activeType }) {
  const filtered = activeType === "all"
    ? opportunities
    : opportunities.filter((o) => o.type === activeType);

  // zero-data: the board has never had a row
  if (opportunities.length === 0) {
    return (
      <div className="empty">
        <p>Nothing here yet -- this is where your jobs, certs,
           and appointments will live.</p>
        <a className="cta" href="/new">Add your first one</a>
      </div>
    );
  }

  // filtered-to-zero: data exists, but this filter matches none of it
  if (filtered.length === 0) {
    return (
      <div className="empty">
        <p>No {activeType}s yet. Try another filter, or add one.</p>
      </div>
    );
  }

  return <div className="grid">{filtered.map(renderCard)}</div>;
}
For this user, the empty state IS the app's first screen

For most apps with a seeded demo database, an empty state is polish you do if there is time. Mine is the exact opposite, and that inversion is the whole argument. My user is, definitionally, someone opening a fresh board with nothing on it -- the parole appointment, the two job leads, and the forklift cert are still in screenshots and a folded-up piece of paper, not in the app yet. The first pixel he ever sees is the empty state. If it is a blank grey rectangle he closes the tab thinking it is broken; if it is a warm line and an obvious button he taps the button. That is not polish, that is whether the app gets used at all.

A note on copy

I spent more time on the sentences than on the code, which felt right. "Nothing here yet" is honest and calm; it does not pretend, it does not apologize, it just says what is true and points at the next step. I cut my first draft, which was a chirpy "No opportunities found!" -- "found" implies a search failed, which reads as an error, which is the exact wrong feeling. The empty state's job is to make absence feel like a beginning, not a bug. For someone in their first ninety days out, the app trying too hard to be cheerful would land worse than a plain, steady sentence.

Deliverable

Two empty states wired off the total and filtered counts: a welcome-plus-CTA for the brand-new board, and a quieter named-filter message for filtered-to-zero. Verified by clicking it on the live URL -- opened the production board with the test rows deleted and saw the welcome, then added one back, tapped the "cert" chip, and saw "No certs yet" instead of a lie. Must-Have four, crossed off. Both Musts for today are done before lunch, which means the Should sweep is unlocked. Commit.
