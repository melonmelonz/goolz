P1 -- the AI summary survives production

The bug has two halves. Half one: the key. OPENAI_API_KEY lives in .env.local, which Vercel never sees, so the deployed route calls the API with no key and the SDK throws. Half two: the route does not catch the throw, so a failed call takes the whole page down with a 500 instead of degrading to a message. I fix the key in the dashboard and the catch in the code. 

// the key, set once in the Vercel project (Settings -> Environment Variables)
// OPENAI_API_KEY = sk-...   (Production + Preview)
// then redeploy so the running build actually has it
// app/api/summarize/route.js -- guard the input, catch the failure
export async function POST(req) {
  const { url } = await req.json();

  // P1 input guard: nothing reaches OpenAI unless it's a real http(s) URL
  if (!url || !/^https?:\/\//i.test(url)) {
    return Response.json(
      { error: "Paste a full job-posting link starting with http." },
      { status: 400 }
    );
  }

  try {
    const posting = await fetchPostingText(url);
    const summary = await summarizeWithOpenAI(posting);
    return Response.json({ summary });
  } catch (err) {
    // degrade, don't crash -- the page stays up, the user gets a sentence
    return Response.json(
      { error: "Couldn't summarize that one -- try the link again or add it by hand." },
      { status: 502 }
    );
  }
}
Degrade, don't crash

The whole P1 is a missing try/catch and a missing env var. The fix is not clever and that is the point -- the AI feature can fail (bad link, OpenAI hiccup, rate limit) and the right behavior is a calm sentence telling my user to try again or add the opportunity by hand, never a stack trace and a dead page. A reentry app a guy is leaning on for a job lead does not get to white-screen because an upstream API blinked.

Verify, don't assume. I tested the fix instead of trusting it -- pasted a real Indeed link on the preview deploy and got bullets back (200); pasted "asdf" and got the 400 message with no API call fired; pulled the env var and redeployed to force the catch, got the friendly 502 message and a page that stayed up. Three paths, three observed outcomes. Commit.

git add .
git commit -m "fix: AI summary degrades instead of 500ing in prod (env var + guard + catch)"

P2 -- the board stops showing stale data after an edit

The PUT was saving fine; the board just was not being told to re-read. In Next.js the fix is to revalidate the path after the mutation so the server component re-fetches and the edited row shows without a hard refresh. 

// app/actions.js -- after a successful update
import { revalidatePath } from "next/cache";

export async function updateOpportunity(id, data) {
  await prisma.opportunity.update({ where: { id }, data });
  revalidatePath("/");   // board re-reads -- the edit shows immediately
}

Verified the same way: edited a card's title from "Warehouse" to "Warehouse -- 2nd shift," hit save, watched the board show the new title with no refresh. Commit. 

git add .
git commit -m "fix: revalidate board after edit so updated row shows without refresh"
If I'm Stuck More Than 20 Minutes
