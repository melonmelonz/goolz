The Last-Mile Cleanup

Exercise 2 / 5 . Level 1 . 25 min

Goal: the unglamorous pass nobody sees and everybody feels. Three small things -- pull the debug logs out of the AI route, finally replace the Week 4 placeholder tagline with the real pitch, and check the layout at 360px where my user's actual phone lives. None of it is hard. All of it is the difference between handing someone a thing that feels finished and handing them a thing that feels like homework with the price tag still on.

Strip the leftover console.logs

The AI route still has the debug logs I left in while chasing the production 500 on Day 1 -- a console.log(summary) and a "got here" log. They do no harm and they do not crash anything, which is exactly why they survive: nothing ever forces you to remove them. But a log dumping the summary into the production console is a tell. It announces that nobody did a final read of this file before it went out the door. 

// app/api/summarize/route.js -- before
const summary = await summarizeWithOpenAI(posting);
console.log("got here, summary:", summary);   // debug from the D1 500 hunt
console.log(posting.slice(0, 200));
return Response.json({ summary });

// after -- the logs are gone, the route says only what it does
const summary = await summarizeWithOpenAI(posting);
return Response.json({ summary });

I grepped the whole app/ tree for console.log to be sure I got all of them, not just the two I remembered. Three total. Gone.

Replace the Week 4 placeholder tagline

The header still reads "your next chapter starts here." I wrote that in Week 4 as a placeholder and it has been quietly sitting at the top of every page for a month, generic enough that I stopped seeing it. It is not the pitch. The pitch is the one I rehearsed in the Day 1 kickoff, the one that names what the app actually does for the actual person. 

// app/components/Header.jsx -- before
<p className="tagline">your next chapter starts here</p>

// after -- the real pitch, the one I can defend at the gate
<p className="tagline">
  jobs, certs, and appointments in one place -- your first 90 days, organized
</p>
Cleanup is a feature the user feels without seeing

Nobody opens the app and thinks "ah, no stray console.logs, no placeholder copy." But they feel it. A generic month-old tagline reads as "the maker stopped paying attention," and a real one-line pitch reads as "this was made on purpose, for me." The user never sees the diff. They feel the difference between a draft and a finished thing, and that feeling is doing real work the first time my user lands on the page.

Check the layout at 360px

Day 1's audit logged the filter chips wrapping into a ragged stack below 380px, and I left it as a P3. Today I open the live URL in devtools at 360px wide -- the width of the cheap Android my user actually has, not the 390px iPhone I keep testing on -- and confirm it. The chips wrap, but raggedly, because they were laid out with right margins instead of a flex gap, so the last row sits misaligned. Small fix. 

/* filter chips -- wrap cleanly at 360px instead of a ragged stack */
.filter-chips {
  display: flex;
  flex-wrap: wrap;
  gap: 8px;            /* even spacing on every row, including the wrapped one */
}
.filter-chips .chip {
  margin: 0;           /* the gap does the spacing now, no stray right margin */
  white-space: nowrap; /* "appointment" never breaks mid-word */
}

At 360px the chips now wrap into two tidy rows, the cards stack instead of overlapping, and the edit affordance is reachable. I scrolled the whole board on the narrow viewport and clicked through create, filter, and delete to be sure nothing else broke at that width.

Checkpoint

Three small things done: zero stray console.logs in the app tree, the real pitch in the header, and a clean layout at 360px. None of it shows up in a feature list. All of it is what separates a student project from a thing a person trusts. Commit it as the cleanup pass it is. 

git commit -m "chore: strip debug logs, real tagline, fix filter-chip wrap at 360px"
