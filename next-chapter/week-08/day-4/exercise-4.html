The CLI Session Demo

Exercise 4 / 5 . Level 2 . 35 min

Goal: show the gate how I built the thing, not just the finished thing. Anyone can present a working app. The CLI session is the evidence of process -- a git history that reads like a story, a test suite running green live, and a deploy. Three artifacts in a terminal that prove there was a method here and not just luck. This exercise is getting the log clean, confirming the suite runs green from the terminal, and rehearsing the narration, because an artifact I can talk through is worth ten times one I can only display.

The git log that reads like a story

The point of git log --oneline here is that conventional commit prefixes turn a list into a narrative. fix: killed a bug, add: landed a feature, update: refined one. Read bottom to top, it is the actual order I built ReEntry Tech in -- schema first, then the AI route, then the build-week fixes. No "wip", no "stuff", no "asdf". A reviewer can read the shape of the project off the log alone. 

$ git log --oneline -10
a1f4c0e update: line-clamp long AI summaries so they stop overflowing the card
7b9e2d1 add: formatDate util for deadlines (TDD, raw ISO -> Jul 14 2026)
3c81a6f fix: reconcile optimistic delete so the old list stops flashing back
e44d7b2 add: empty state on the board (zero-data + filtered-to-zero copy)
9a2f5c8 fix: AI summary degrades instead of 500ing in prod (env + guard + catch)
6e0d1b9 add: client-side type filter and search over the board
2d6b0a3 update: trim-and-presence validation so blank titles can't insert
5f1c9e7 add: AI summary route -- paste a job URL, get plain-language bullets
b8c3f02 add: full CRUD on Opportunity against Postgres through Prisma
0b3a8d4 add: Opportunity + Category schema, one-to-many relation

I am going to narrate this, not just scroll it. Point at the bottom -- "this is the schema and the relationship going in first" -- and walk up: CRUD, then the AI route, then the filter, then the build-week fix: and update: commits where I hardened it for real users. Reading it out loud is the proof that I know what every commit was for. A log I can narrate is a log I lived.

The suite running green, live

Then I run the tests in the terminal in front of them. Not a screenshot of green -- the actual command, the actual pass. This is the moment the AI-touch story from the last exercise becomes concrete: the tests that pin the summary shape are right there, passing, where anyone can see them. 

$ npx vitest run

 RUN  v1.6.0  /home/penn/reentry-tech

 ✓ lib/formatDate.test.js (4)
 ✓ lib/getDomain.test.js (3)
 ✓ app/api/summarize/summarize.test.js (5)
 ✓ app/api/board/route.test.js (2)

 Test Files  4 passed (4)
      Tests  14 passed (14)
   Start at  09:41:02
   Duration  1.12s

The line I say over this: "These are the pure utils, the AI summary parsing, and the board GET handler with Prisma mocked -- fourteen tests, all green, run live so you're watching them pass, not trusting a screenshot." Running it live is a small flex and it lands, because everyone in the room knows a screenshot of green could be from last week.

The deploy

And the last artifact: a deploy. I do not need to do a full production push on stage, but I show the command and the fact that this is how the live URL got there -- the same URL they can open on their phone. Process, product, and the bridge between them in one terminal. 

$ git push          # Vercel builds + deploys on push to main
$ npx prisma migrate deploy   # the database half, separate from the code half

  Vercel  Production  https://reentry-tech.vercel.app   Ready
The commits ARE the story of how I work

I used to think a clean git history was housekeeping -- nice to have, nobody looks. Today it flipped: the log is a thing I can show instead of a claim I have to make. "I worked methodically" is a thing I'd have to ask them to believe. A log that reads schema -> CRUD -> feature -> fix -> fix, in conventional-commit prose, is that same claim as evidence they can read themselves. The history is the most honest artifact I have, because I can't fake it after the fact -- it's the literal record of the order I made decisions in.

Checkpoint

A three-part CLI session rehearsed end-to-end: a git log --oneline that narrates as a story from schema to hardening, the Vitest suite run live to green (14 passing), and the deploy command that ties the process to the live URL. Each artifact paired with a sentence I say while it is on screen, because the narration is the part being graded -- showing process, not just product. Walked through twice so the terminal commands and the talking line up.
