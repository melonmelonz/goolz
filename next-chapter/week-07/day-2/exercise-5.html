The README, With a Data Model

Exercise 5 / 6 . Level 2 . 30 min

Goal: a README that a stranger could run the project from, that next-Monday-me can resume from, and that Codex CLI can take context from -- with a Data Model section that doubles as my Phase 2 gate script. I had the AI draft it from my description, then rewrote about half of it, because the draft described a very impressive app that was not quite mine. Template-sounding lines went first.

What landed in README.md

# ReEntry Tech

A board where partner organizations post jobs, certifications, and
services for people coming home from incarceration -- and where the
people looking can actually find them.

## Features
- Post a listing (title, description, type) via a validated form
- Browse all listings, newest first, with client-side search
- Listing detail pages, with other listings from the same org
- Edit listings -- pre-filled form, Server Action mutation
- Delete listings, with a confirmation dialog in front

## Tech Stack
- Next.js (App Router) -- JavaScript, server components by default
- PostgreSQL via Prisma ORM
- Vitest for tests (mocked Prisma -- no test DB needed)
- Plain CSS. No framework. It is a board, not a spaceship.

## Data Model
Opportunity
- id           Int, primary key, autoincrement
- title        String, required
- description  String, optional -- quick posts may lack a writeup
- type         String, default "job" -- job | certification | service
- location     String, optional
- remote       Boolean, default false
- active       Boolean, default true
- createdAt    DateTime, set on insert

Organization (one-to-many: one org posts many opportunities)
- id, name, email, verified, createdAt
- Opportunity.orgId -> Organization.id

## Getting Started
1. npm install
2. Copy .env.example to .env, set DATABASE_URL
3. npx prisma migrate dev
4. npm run dev, open http://localhost:3000

## Project Structure
- app/                 pages and layouts (server components)
- app/api/             HTTP routes -- GET/POST collection, GET/PUT/DELETE [id]
- app/opportunities/   the board, edit page, actions.js (Server Actions)
- prisma/              schema + migrations
- lib/                 prisma client singleton

## Status
Works: full CRUD, search, detail pages, 12 passing tests.
In progress: nothing mid-flight -- clean checkpoint as of W7D2.
Planned: third-party API integration (W7D3), auth eventually.
Known wart: delete button can be double-clicked; second click
loses politely (P2025 -> 404) but should be disabled.
What I rewrote out of the AI draft

The draft opened with "A modern, full-stack web application leveraging Next.js" -- which describes ten million repos and therefore none. The one-sentence test for a README opener is whether it could be pasted onto a different project without anyone noticing; mine now cannot. I also added the Known wart line myself. The AI does not volunteer flaws, and a Status section that only lists triumphs is marketing, not status. The honest wart line is the part next-Monday-me will be most grateful for.

Why the Data Model section earns its place

Two consumers. The Phase 2 gate next week has a verbal walkthrough of my schema, and this section is the rehearsal script -- I read it aloud twice and the "one org, many opportunities" sentence already comes out smoother. And every Codex CLI session from now on gets this file as context, which means no more guessing whether the field is type or category, no more inventing a userId that does not exist. The schema has not changed since Week 6; writing it out in prose was the refresh the course said it would be -- I had honestly forgotten active was in there.

Checkpoint

README committed. The test I ran on it: scrolled to the top and read it as someone who has never seen the project. What is it -- clear in one sentence. How do I run it -- four steps, and I actually ran them in a scratch clone to verify, because a setup section nobody has executed is a rumor. Status -- honest, warts included. It is the first README I have written that I expect to read again.
