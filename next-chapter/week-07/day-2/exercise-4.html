The thing the checklist flushed out

Between UPDATE and DELETE I did something the checklist did not ask for: opened the edit page for a listing in one tab, deleted that listing in another, then hit save in the first tab. The action threw P2025 -- correctly, my Exercise 1 test promised exactly that -- but "correctly threw" rendered as Next's unhandled-error screen, which is the right behavior wearing the wrong face. A user who lost a race should get a sentence, not a stack trace. 

// the fix: catch the stale case at the action's edge
try {
  updated = await prisma.opportunity.update({ where: { id }, data });
} catch (error) {
  if (error.code === "P2025") {
    redirect("/opportunities?gone=1");   // listing vanished; back to the board
  }
  throw error;
}

The board reads the query param and shows a one-line notice: "That listing was removed while you were editing." The redirect-throws gotcha from Exercise 2 bit me again here -- redirect inside a catch is fine, but it cannot be inside a try that I also catch. Rearranged, retested, suite still green plus one new test pinning the P2025-redirects behavior.

Why I tested a race the checklist did not mention

Because the checklist tests the app as one careful user, and no app has one careful user. Two tabs is the cheapest possible simulation of two people, and a board whose whole purpose is multiple orgs posting listings is going to have writes crossing in the mail. Yesterday's exercise: the failing test forced me to decide what a missing row means. Today's checkpoint: the running app forced me to decide what it means to a person looking at a screen. Both decisions existed whether or not I made them -- making them is the job.

Checkpoint, certified

Create, read, update, delete -- all four, end to end, against a real Postgres, with eleven green tests underneath and one race condition now handled like a sentence instead of a crash. Screen recording captured for the deliverable: one item taken through its full life, creation to deletion, forty seconds. The app is complete in the load-bearing sense: everything from here is addition, not foundation.
