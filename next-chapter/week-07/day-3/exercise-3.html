Break It on Purpose

Exercise 3 / 9 . stretch . Level 2 . 25 min

Goal: prove the advice route survives the three classic external-API failures -- their server errors, their format changes, their server hangs -- by inducing each one and watching what my user would see. Same instinct as Tuesday's two-tab race: the checklist tests the happy path, so I test the others.

Failure 1 -- their server errors

Changed the URL to /advicexxx. Their server returns a 404, my !response.ok branch catches it, my route returns the failure honestly, and the board renders without the advice line -- the silent-decoration decision from Exercise 2 paying off immediately. No crash, no red text, no leaked third-party error JSON into my UI.

Failure 2 -- the shape changes under me

Simulated by pointing the parse at a field that does not exist. data?.slip?.advicezzz ?? null flows a clean null through the contract, component sees no advice, renders nothing. Without the optional chaining this is TypeError: cannot read properties of undefined -- the classic 2am page -- and with it, it is a non-event. Cheapest insurance in JavaScript.

Failure 3 -- the hang, and the modern timeout

const response = await fetch("https://api.adviceslip.com/advice", {
  cache: "no-store",
  signal: AbortSignal.timeout(5000),   // built into Node 18+; no manual
});                                     // AbortController + setTimeout dance

// in the catch, narrow before assuming:
catch (error) {
  if (error instanceof Error && error.name === "TimeoutError") {
    return NextResponse.json(
      { error: "Advice service took too long" }, { status: 504 });
  }
  return NextResponse.json(
    { error: "Could not reach advice service" }, { status: 503 });
}
Why this beats the pattern most tutorials show

The older recipe is a hand-rolled AbortController, a setTimeout to call abort(), and a clearTimeout you must remember in every exit path or you leak the timer. AbortSignal.timeout(ms) is the same machinery as a one-liner primitive -- no cleanup branch to forget. Worth recognizing the old pattern on sight, though, because the AI was trained on a decade of it; when Codex CLI suggested the manual version first, I asked for the built-in and got it. Knowing the modern primitive is what made that a review instead of an acceptance.

504 vs 503, the distinction I now actually hold

503: I could not reach them, or they are down -- unavailability. 504: I reached out and they never answered in time -- a timeout at the gateway, which is what my route is in this picture. Nothing in my little advice feature treats them differently today, but the codes are free to get right now and expensive to untangle later, and a future log line that says 504 tells me "slow upstream" without a single extra word.

Testing the timeout honestly: Advice Slip is rude enough to be slow sometimes but not reliably, so I pointed the fetch at httpstat.us/200?sleep=8000 -- a service that exists to dawdle on command -- and watched the 504 fire at the five-second mark. Then put the real URL back. Break it on purpose, with instruments.

Checkpoint

Three failure modes, three induced failures, three distinct honest responses, zero crashes, and the board never looked anything but calm. URL restored, verified green. The pattern I am taking forward to the OpenAI route in the next exercise: ok-check, optional-chain the parse, timeout the hang, and give every failure its own status and sentence.
