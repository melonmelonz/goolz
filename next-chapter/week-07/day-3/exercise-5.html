A Small Chat UI

Exercise 5 / 9 . stretch . Level 1 . 25 min

Goal: a page at /ai-chat where typing a question and clicking Ask produces an answer. The shape is the standard controlled-form-plus-fetch from Week 6 -- the AI behind the route changes nothing about the React in front of it, which is itself the lesson.

The page

// app/ai-chat/page.js
"use client";
import { useState } from "react";

export default function AIChatPage() {
  const [input, setInput] = useState("");
  const [response, setResponse] = useState("");
  const [loading, setLoading] = useState(false);

  async function handleSubmit(e) {
    e.preventDefault();
    if (!input.trim()) return;
    setLoading(true);
    setResponse("");
    try {
      const res = await fetch("/api/ai", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ prompt: input }),
      });
      const data = await res.json();
      setResponse(data.message || data.error);
    } catch {
      setResponse("Something went wrong. Try again.");
    }
    setLoading(false);
  }

  return (
    <main className="chat">
      <h1>Assistant</h1>
      <form onSubmit={handleSubmit}>
        <input value={input} onChange={(e) => setInput(e.target.value)}
               placeholder="Ask something..." />
        <button type="submit" disabled={loading}>
          {loading ? "Thinking..." : "Ask"}
        </button>
      </form>
      {response && <div className="bubble">{response}</div>}
    </main>
  );
}
The blocking pattern, named and accepted

This waits for the whole completion and then shows it -- no word-by-word streaming, which is why my page feels different from ChatGPT even though it is the same engine. Streaming is Week 9; the blocking version is easier to reason about and easier to debug, and for two-to-three-sentence responses the wait is barely two seconds. The disabled={loading} matters more here than on past forms, though: every click costs actual fractions of a cent, so the button locking during flight is cost control wearing a UX costume. Tuesday's double-click delete bug, same species, smaller teeth.

"What should I make for dinner?"pasta, stir-fry, tacos -- cheerful, unmoored from anything. The control group for Exercise 6

The first and third answers are the interesting pair: both are competent and neither knows where it is. The reentry question deserved an answer shaped by this app -- what is actually on the board -- and got a horoscope instead. That gap is precisely what the system message (next exercise) and the data connection (the one after) exist to close. The haunted feeling of a text box in my own app talking back lasted about ninety seconds before it was replaced by wanting the ghost to be useful.

Checkpoint

Working chat at /ai-chat: type, ask, Thinking, answer in a bubble. Three questions, three reasonable-or-revealing answers, button locked during flight, errors land as a sentence instead of a blank. Deliverable demoed. The page is a test harness more than a feature -- the feature comes in Exercise 8 -- but it is the harness I will poke the next two exercises with.
