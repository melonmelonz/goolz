First OpenAI Call

Exercise 4 / 9 . core . Level 1 . 35 min

Goal: a route at /api/ai that takes a prompt and returns a completion from the same engine behind ChatGPT. Marquee example, same pattern as the advice route: external API, server-side call, key on the server, try/catch at the boundary. The payload is a messages array instead of a URL query, and the response costs money instead of nothing. Otherwise: the dog photo API with better conversation.

Setup, including the part that cost ten minutes

Key created at platform.openai.com, named reentry-dev, copied immediately because the dialog means it about not showing you twice. Spending limit set to $5 first -- before the key existed to spend anything -- because the lecture's "accidental infinite loop" scenario describes a person I have been. Then: 

# .env
OPENAI_API_KEY="sk-proj-..."

npm install openai

The ten minutes: first call returned a 401 with a perfectly good key, because the dev server had been running since before the key existed and Next reads .env at startup. Restarted, worked. The lecture literally warned about this and I hit it anyway, which is the usual relationship between warnings and experience.

The route

// app/api/ai/route.js
import { NextResponse } from "next/server";
import OpenAI from "openai";

const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

export async function POST(request) {
  try {
    const { prompt } = await request.json();

    if (!prompt || !prompt.trim()) {
      return NextResponse.json(
        { error: "Prompt is required" }, { status: 400 });
    }

    const response = await openai.chat.completions.create({
      model: "gpt-5-mini",
      messages: [
        { role: "system",
          content: "You are a helpful assistant. Keep responses concise -- 2-3 sentences." },
        { role: "user", content: prompt },
      ],
      temperature: 0.7,
    });

    return NextResponse.json({
      message: response.choices[0].message.content,
      usage: response.usage,   // tokens in/out -- I want to SEE the meter
    });

  } catch (error) {
    console.error("OpenAI API error:", error);
    return NextResponse.json(
      { error: "Failed to get AI response" }, { status: 500 });
  }
}
Why I return usage to myself

Not part of the assignment. But tokens are the meter and I wanted the meter visible from day one, so every response carries its own receipt: my first call was prompt_tokens: 31, completion_tokens: 58 -- about two hundredths of a cent, exactly as advertised. Seeing the real number did more for my cost intuition than the pricing table did; the table says cheap, the receipt proves cheap, and the habit of looking will matter the day a prompt accidentally carries fifty database rows.

The test page, and the moment

The lab's minimal test page: one button, "Ask AI," wired to POST { prompt: "Explain what an API is in one sentence." } at my route. Clicked it. One second of Thinking, then: "An API is a defined way for one program to request data or actions from another, like a menu of things you can ask a service to do."

And the moment is worth being honest about: that text was generated by the model I have been talking to all course, except this time nothing about it was a chat product -- no interface, no account session, just my route, my key, my JSON. The ChatGPT window is steps 1 and 5 of a five-step loop and I now own the middle three. Every AI feature in every app I use stopped being a feature and became this exact POST request wearing different clothes.

Checkpoint

Working route at /api/ai, real completion on the test page, usage receipt in every response, no errors in the terminal, key in .env and nowhere else -- verified with a git grep sk-proj that found nothing, which is the only acceptable result of that command for the rest of my life.
