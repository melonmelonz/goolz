Integrate Through My Own Route

Exercise 2 / 9 . core . Level 1 . 30 min

Goal: the full pattern, end to end -- a Next route that calls the external API server-side, and a piece of UI that consumes my route, with loading and error states. The board gets one quiet line of borrowed wisdom under its header. Small by design: the pattern is the deliverable, the advice is the excuse.

The route

// app/api/advice/route.js
import { NextResponse } from "next/server";

export async function GET() {
  try {
    const response = await fetch("https://api.adviceslip.com/advice", {
      cache: "no-store",   // Next caches fetches by default; randomness
                           // that never changes is just a constant
    });

    if (!response.ok) {
      return NextResponse.json(
        { error: "Advice service unavailable" },
        { status: response.status }
      );
    }

    const data = await response.json();
    return NextResponse.json({ advice: data?.slip?.advice ?? null });

  } catch {
    return NextResponse.json(
      { error: "Could not reach advice service" },
      { status: 503 }
    );
  }
}
The reshaping is the point

The external response is { slip: { id, advice } }; my route returns { advice }. That flattening is not cosmetic -- it is the boundary doing its job. My UI depends on my contract, so if Advice Slip ever renames slip to quote, the blast radius is one line in one route file instead of every component that ever touched the data. The optional chaining with a null fallback handles the "format changed under you" failure mode the lecture warned about: missing field becomes null, not a crash at midnight.

The UI -- a client island on a server board

// app/opportunities/AdviceLine.js
"use client";
import { useState, useEffect } from "react";

export default function AdviceLine() {
  const [advice, setAdvice] = useState(null);
  const [state, setState] = useState("loading");

  useEffect(() => {
    fetch("/api/advice")
      .then((r) => r.json())
      .then((d) => {
        if (d.advice) { setAdvice(d.advice); setState("ok"); }
        else setState("error");
      })
      .catch(() => setState("error"));
  }, []);

  if (state === "loading") return <p className="advice">...</p>;
  if (state === "error") return null;   // decoration fails silent
  return <p className="advice">&ldquo;{advice}&rdquo;</p>;
}
Why the error state is invisible

The lab checklist wants an error message shown, and for a feature the user came for -- the listings -- it would get one. But the advice line is decoration, and decoration that apologizes for itself is worse than decoration that is absent. A red "Error: could not load advice" above a job board is noise pretending to matter. So: loading shows a quiet ellipsis, failure shows nothing, success shows the line. The route still returns proper errors -- the contract is honest -- the component just chooses not to perform its grief. Deviating from the checklist on purpose and writing down why feels like the actual lesson.
